# 📏 Стиль кода и соглашения

Этот документ — про то, как писать код, чтобы он был понятен другим и не конфликтовал с движком. Соглашения сложились исторически, но соблюдаются последовательно — новый код должен им соответствовать.

---

## Общие принципы

1. **Не трогайте ядро.** Любая доработка должна жить в модуле, блоке, хуке или теме. Если для задачи не хватает точки расширения — это повод предложить её в issue, а не править `system/core/`.
2. **Расширение вместо правки.** Хук лучше форка, оверрайд шаблона лучше правки `templates/default`, свои строки лучше правки чужих файлов.
3. **Простота важнее абстракции.** Движок намеренно обходится без фреймворка: прямой PHP, обычный SQL, никаких «умных» конструкций.
4. **Сайт должен работать.** Код, который «почти готов», лучше не коммитить.

---

## Форматирование PHP

- Отступы — **4 пробела** (табуляция в проекте не используется).
- Открывающий тег — `<?php` без закрывающего `?>` в файлах, которые содержат только PHP.
- Файлы — **UTF-8 без BOM**, перевод строки — `\n`.
- Фигурные скобки у классов и методов — на той же строке.

```php
<?php

class ReviewController extends Controller
{
    public function indexAction()
    {
        $reviews = $this->reviewModel->getPublished(10);

        return $this->render('reviews/index', [
            'reviews' => $reviews,
        ]);
    }
}
```

- Открывающая скобка метода переносится (стиль PSR-2/12).
- Между методами — пустая строка.
- Длинные вызовы разбиваются по аргументам.

## Именование

| Элемент | Стиль | Пример |
|---|---|---|
| Классы | `PascalCase` | `ReviewController`, `ReviewModel`, `ReviewAction` |
| Классы в модуле | с суффиксом роли | `<Модуль>Controller`, `<Модуль>Model`, `<Модуль>Action` |
| Экраны | `<Действие>.php` | `Index.php`, `AdminCreate.php`, `Show.php` |
| Методы и функции | `camelCase` | `getPublishedPosts()`, `buildPage()` |
| Действия контроллера | `<action>Action()` | `adminIndexAction()`, `showAction($slug)` |
| Переменные | `camelCase` | `$currentPage`, `$postId` |
| Файлы | `snake_case` для «многословных» | `navigation_helper.php`, `events.php` |
| Константы | `UPPER_SNAKE_CASE` | `LANG_ACTION_REVIEWS_INDEX_PAGE_TITLE` |
| Таблицы | `snake_case` | `post_blocks`, `user_achievements` |
| Тексты локали | `LANG_<ОБЛАСТЬ>_<МОДУЛЬ>_<ЧТО>` | `LANG_CONTROLLER_POSTS_MANIFEST_NAME` |

Международные аббревиатуры в коде не пишутся заглавными: `$html`, `$url`, `$api` — не `$HTML`.

## Структура файлов

```php
<?php
/**
* Кратко: что делает класс
* @package reviews\actions
*/

namespace reviews\actions;

class Index extends ReviewAction
{
    // 1. Свойства
    // 2. Конструктор
    // 3. Публичные методы (сначала главный — execute)
    // 4. Защищённые и приватные
}
```

```text
system/controllers/reviews/

├── Model.php
├── manifest.php
├── routes.php
├── permissions.php
├── Settings.php
├── actions/

```

## Работа с выводом

```php
<?php
// В шаблонах — короткие echo-теги
<h1><?= html($post['title']) ?></h1>

// Экранирование обязательно
<?= html($user['display_name']) ?>

// Для контента, прошедшего очистку, экранирование не применяется
<?= $post['content'] ?>
```

Тексты берутся из констант, а не пишутся строкой:

```php
<?php
// Плохо
echo 'Комментарий сохранён';

// Хорошо
echo LANG_ACTION_COMMENTS_ADD_SUCCESS;
```

## Работа с данными

```php
<?php
// Подготовленные запросы — обязательно
$post = $db->fetch("SELECT * FROM posts WHERE slug = ?", [$slug]);

// Явные типы при получении числовых значений
$count = (int) $db->fetchValue("SELECT COUNT(*) FROM posts");

// Транзакции для нескольких изменений
$db->beginTransaction();
try {
    // …
    $db->commit();
} catch (\Throwable $e) {
    $db->rollBack();
    throw $e;
}
```

- Модель не возвращает HTML и не знает о шаблонах.
- Экшен не пишет SQL напрямую, если для этого есть модель.
- Валидация данных — до записи в базу.

## JS и CSS

- Свой код — в отдельных файлах темы, не в `<script>` внутри шаблонов.
- Подключение — через функции ассетов (`front_css`, `front_js`, `add_bottom_js`).
- Данные из PHP в JS — через `js_config()` / `js_var()`, а не склейкой строк.
- Классы CSS — в стиле Bootstrap-темы (`post-block-quote`, `admin-menu-item`), без односложных имён (`q`, `bx`).
- Минифицированные библиотеки не редактируются.

## Комментарии и документация

- Комментарии — по-русски, в стиле проекта; поясняют **зачем**, а не «что очевидно».
- PHPDoc — для классов, методов с нетривиальными параметрами и для возвращаемых структур.

## Безопасность — часть стиля

Код, который плохо защищён, не проходит ревью:

```php
<?php
// Минимальный набор «хорошего» экшена
if (!AuthHelper::can('review_edit')) {
    Notification::error(LANG_ACTION_REVIEWS_NO_PERMISSION);
    $this->controller->redirect(ADMIN_URL . '/reviews');
}

if (!$this->csrfValid($_POST['csrf_token'] ?? '')) {
    Notification::error(LANG_ACTION_REVIEWS_INVALID_CSRF);
    $this->controller->redirect(ADMIN_URL . '/reviews');
}

$title = trim((string) ($_POST['title'] ?? ''));
// …валидация и только потом запись
```

## Чек-лист ревью

Перед тем как предложить изменение:

| ✔ | Пункт |
|---|---|
| ☐ | Ядро не изменено (или изменение обосновано и предложено отдельно) |
| ☐ | Новый функционал — в модуле/блоке/хуке/теме |
| ☐ | Все строки интерфейса — в языковых файлах |
| ☐ | Вывод экранируется, SQL — с параметрами |
| ☐ | Права проверяются в экшенах |
| ☐ | Код протестирован на «чистой» установке (если меняет установку или миграции) |
| ☐ | Нет отладочных `var_dump()`, `exit`, закомментированного «на память» кода |
| ☐ | Форматирование соответствует проекту (4 пробела, PSR-2) |
| ☐ | Добавлена документация, если меняется публичное поведение |

## Как проверить свой код

1. **Синтаксис:** `php -l system/controllers/reviews/ReviewController.php`.
2. **Реальный сценарий:** пройдите путь пользователя руками — от страницы до сохранения.
3. **Ошибки:** включите `debug_mode` и посмотрите `/admin/debug` после сценария.
4. **Права:** проверьте поведение под гостем, пользователем и администратором.
5. **Мобильные:** откройте страницу в мобильном режиме браузера.
6. **Скорость:** проверьте консоль/сеть на лишние запросы и 404.
