# 🧩 Пользовательские поля

Пользовательские поля — это способ добавить к сущностям свои данные, не меняя базу и не трогая код. Создали поле «Подзаголовок» для постов — оно появилось в форме поста и доступно в теме.

Настраивается в разделе **Поля** (`/admin/fields`).

---

## К каким сущностям можно привязать поле

| Тип сущности | Что получит поле |
|---|---|
| `post` | Посты: дополнительная информация, характеристики, ссылки |
| `page` | Страницы: реквизиты, контакты, реквизиты компании |
| `category` | Категории: подзаголовок, баннер, акцентный цвет |
| `user` | Пользователи: профильные данные |

У фрагментов — собственная система полей (см. [Блоки и фрагменты](04-bloki-i-fragmenty.md)).

---

## Типы полей

Всего доступно 12 типов + вспомогательные элементы формы.

| Тип | Ключ | Что хранит и как выглядит |
|---|---|---|
| Строка | `string` | Короткий текст в одну строку |
| Текст | `text` | Многострочное поле с редактором |
| Число | `number` | Число с ограничениями `min` / `max` |
| Дата | `date` | Дата через календарь |
| Цвет | `color` | Выбор цвета (палитра) |
| Выпадающий список | `select` | Один вариант из списка |
| Мультивыбор | `multiselect` | Несколько вариантов |
| Флажок | `flag` | Да/нет (переключатель) |
| Изображение | `image` | Файл-картинка с превью |
| Ссылка | `link` | URL с подписью |
| Иконка со стилем | `icon_with_style` | Иконка + цвет/размер |
| HTML | `html` | Произвольная разметка |

**Вспомогательные элементы** (доступны в конструкторах форм и полях блоков):

| Элемент | Зачем |
|---|---|
| `alert` | Информационная врезка внутри формы |
| `repeater` | Повторяющаяся группа полей |
| `blockImage` | Картинка внутри настроек блока |

## Создание поля

1. Откройте **Поля** и выберите сущность: например, «Посты».
2. Нажмите **«Создать поле»**.
3. Заполните:

| Параметр | Значение |
|---|---|
| **Название** | Как поле подписано в форме: «Подзаголовок» |
| **Системное имя** | Латиницей, без пробелов: `subtitle`. Используется в коде и шорткодах |
| **Тип** | Из таблицы выше |
| **Описание / подсказка** | Пояснение для редактора |
| **Обязательное** | Нельзя сохранить сущность без значения |
| **Активно** | Выключенное поле не отображается и не обрабатывается |
| **Показывать в записи** | `show_in_post` — выводить ли значение в карточке материала |
| **Показывать в списке** | `show_in_list` — выводить ли в списке |
| **Настройки типа** | Для `select` — варианты, для `number` — границы, для `image` — ограничения и т. д. |

4. Сохраните. Поле сразу появится в форме создания/редактирования постов или страниц.

> [!TIP]
> Системное имя — это API поля. Выбирайте его один раз и надолго: переименование сломает шорткоды и шаблоны, где поле уже используется.

---

## Как вывести значение на сайте

### 1. Через шорткод (самый простой путь)

Каждое активное поле автоматически получает шорткод вида `{сущность_системное_имя}`:

```text
{post_subtitle}          — подзаголовок поста
{page_phone}             — телефон со страницы
{category_banner}        — баннер категории
```

Если значение нужно подставить в конкретной сущности, укажите её идентификатор (синтаксис базовых шорткодов `{field ...}`):

```text
{field name="subtitle" type="post" id="12" default="—"}
{field_display name="subtitle" type="post" id="12"}
```

- `{field ...}` — «сырое» значение (экранируйте при выводе в атрибутах).
- `{field_display ...}` — значение с учётом оформления типа (например, картинка выводится как `<img>`, цвет — как плашка).
- `default` — что показать, если значение пустое.

### 2. Через хелперы в шаблонах

```php
<?php
// Значения полей сущности
$fields = get_custom_fields('post', $post['id']);

// Одно значение
$subtitle = get_custom_field_value('subtitle', 'post', $post['id']);

// Готовый вывод (для изображений, иконок, цветов)
echo get_custom_field_display('subtitle', 'post', $post['id']);

// Есть ли значение
if (has_custom_field('subtitle', 'post', $post['id'])) { /* ... */ }
```

### 3. Особые случаи

- **Иконки** — `render_icon_field()` и `get_icon_field_data()`.
- **Повторители** — выводятся циклом: данные приходят массивом, каждая строка содержит поля группы.

## Практические сценарии

| Задача | Решение |
|---|---|
| Дополнительный подзаголовок в карточке поста | Поле `string` с `show_in_list` |
| Характеристики товара/услуги | Несколько полей `string` + `number` |
| Баннер категории | Поле `image` для сущности `category` |
| Контактный телефон в подвале | Поле `string` на странице «Контакты» |
| Набор ссылок (соцсети) | Поле `repeater` со вложенными `link` |
| Бейдж «Проверено» | Поле `flag`, вывод в шаблоне условием |

## Частые вопросы

**Поле не появилось в форме.** Проверьте, что оно **активно** и привязано к нужной сущности (`entity_type`).

**Как удалить поле?** Кнопка удаления в списке. Значения полей удаляются вместе с полем — если данные важны, сначала выгрузите их из таблицы `field_values`.

**Можно ли использовать одно поле в постах и на страницах?** Нет — поле принадлежит одной сущности. Создайте два поля с одинаковым системным именем для разных сущностей.

**Как вывести поле в конкретном блоке?** В настройках блока включите поддержку полей или используйте шорткод — блоки обрабатывают шорткоды автоматически.
