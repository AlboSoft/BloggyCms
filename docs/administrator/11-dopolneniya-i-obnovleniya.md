# 📦 Дополнения и обновления

Движок расширяется **пакетами**: ZIP-архив с описанием и файлами устанавливается прямо из админки. Обновление самого движка — тоже управляемая процедура, а не «залейте папку целиком».

Раздел: **Дополнения** (`/admin/addons`).

---

## Установка дополнения

1. Скачайте пакет (`.zip`) у разработчика.
2. В админке откройте **Дополнения → Установить пакет** (`/admin/addons/install`).
3. Загрузите архив. Движок:
   - распаковывает его во временную папку `uploads/temp_addon/`;
   - **проверяет структуру и описание** (`admin/addons/analyze`);
   - показывает, что за пакет, какая версия, автор, что будет установлено;
   - проверяет, не установлен ли пакет уже и подходит ли версия.
4. Подтвердите установку. Движок:
   - создаёт резервную копию заменяемых файлов;
   - копирует содержимое `files/` в корень сайта;
   - выполняет `install.php`, если он есть в пакете;
   - регистрирует пакет в таблице `installed_addons`.
5. Проверьте сайт и админку.

> [!NOTE]
> Для распаковки нужен модуль PHP **ZipArchive**. Максимальный размер пакета — 50 МБ. Системное имя пакета генерируется из его названия (кириллица транслитерируется).

## Формат пакета

Архив — это папка со **строго фиксированной структурой**:

```
my-addon.zip
├── package.ini          # описание пакета (обязательно)
├── files/               # файлы, которые будут скопированы в корень сайта (обязательно)
│   └── system/controllers/my_module/...
└── install.php          # необязательный скрипт установки
```

### `package.ini`

```ini
[info]
title = "Мой модуль"          ; до 64 символов; из него генерируется system_name

[version]
major = 1
minor = 0
build = 0
date = 2026-05-05             ; необязательно

[author]
name = "Иван Иванов"          ; необязательно
url = "https://example.com"   ; необязательно
email = "ivan@example.com"    ; необязательно

[description]
text = "Что делает пакет и зачем он нужен."   ; можно несколько строк

[install]                     ; блок для первичной установки
type = install

[update]                      ; блок для обновления ранее установленного пакета
type = update
version = 1.0.0               ; версия, С которой обновляем
```

**Как определяется тип пакета:** если в `package.ini` есть блок `[install]` — это установка; если `[update]` — обновление, причём версия `version` должна совпадать с установленной, иначе движок откажется обновлять во избежание скачка через версии.

### `install.php`

Необязательный скрипт, выполняется после копирования файлов. Внутри доступны `$db`, `$package` и `$getPrefix()`:

```php
<?php
/** @var mixed $db Подключение к базе */
/** @var array $package Информация о пакете */

$prefix = $getPrefix();

$db->query("CREATE TABLE IF NOT EXISTS `{$prefix}my_table` (
    `id` INT AUTO_INCREMENT PRIMARY KEY,
    `title` VARCHAR(255) NOT NULL
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4");

// Верните false, чтобы движок счёл установку неуспешной
return true;
```

> [!WARNING]
> Скрипт установки выполняется **с полными правами движка**. Устанавливайте пакеты только из источников, которым доверяете. Для своего сервера правило простое: незнакомый пакет — сначала прочитайте `install.php` и содержимое `files/` глазами.

## Управление установленными дополнениями

| Действие | Маршрут |
|---|---|
| Список | `/admin/addons` |
| Информация о пакете | `/admin/addons/info/{id}` |
| Проверить обновления | `/admin/addons/check-updates` |
| Удалить | `/admin/addons/delete/{id}` |

Удаление снимает пакет с учёта; файлы, которые он добавил, и созданные таблицы нужно удалять по инструкции автора пакета (движок не знает, что именно изменил скрипт установки).

## Обновление движка

Версия движка хранится в `system/config/version.ini`, проверка сравнивает её с последним релизом.

| Шаг | Что делать |
|---|---|
| 1 | Отключить режим отладки (`general.debug_mode`), если он мешал работе |
| 2 | Сделать **бэкап базы** и папки `uploads/` |
| 3 | Скачать нужный релиз из репозитория движка |
| 4 | Заменить файлы движка: `index.php`, `system/`, `templates/default/`, `.htaccess` |
| 5 | **Не перезаписывать:** `system/config/config.php`, `system/config/database.php`, `uploads/`, свою тему в `templates/` |
| 6 | Открыть сайт и админку, проверить работу |
| 7 | Нажать «Проверить обновления» в админке — версия должна определиться корректно |

**Что не ломается при обновлении:** контент в базе, загруженные файлы, настройки, ваша тема, ваши модули (если не переопределяют изменённые части ядра).

> [!TIP]
> Обновляйтесь на копии сайта (staging), когда есть сомнения: скопируйте базу и файлы на поддомен, обновите там, проверьте, потом повторите на боевом сайте.

## Удаление установщика

После того как сайт заработал, папку `install/` нужно удалить. В админке есть кнопка в один клик: `/admin/delete-install-folder`.

Вручную:

```bash
rm -rf /путь/к/сайту/install
```

> [!WARNING]
> Пока `install/` существует, любой желающий может заново запустить мастер установки. Это критично для безопасности — не оставляйте папку «на всякий случай».

## Частые вопросы

**Пакет не устанавливается с сообщением о структуре.** Проверьте, что в корне ZIP лежат именно `package.ini` и папка `files/` — а не вложенная папка вида `my-addon/package.ini`.

**Ошибка «уже установлен».** Пакет с таким `system_name` есть в `installed_addons`. Удалите прежнюю версию или выпустите пакет как обновление (`[update]`).

**Куда делись старые файлы при установке?** Движок делает резервную копию во временной папке и затем её очищает; постоянных бэкапов пакетов не остаётся — поэтому общий бэкап сайта перед установкой обязателен.

**Обновление движка сбрасывает мои правки в `templates/default`?** Да, файлы стандартной темы заменяются. Правки храните в своей теме или в отдельных файлах-оверрайдах.
