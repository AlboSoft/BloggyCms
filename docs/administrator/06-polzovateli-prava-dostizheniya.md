# 👥 Пользователи, права и достижения

Раздел **Пользователи** (`/admin/users`) отвечает за аккаунты сайта: кто может писать комментарии, кто видит закрытые материалы, кто получает достижения.

---

## Пользователи

### Список и фильтры

`/admin/users` показывает аккаунты с фильтрами по:

- **статусу** — активные / заблокированные;
- **группе**;
- **дате регистрации** — за день или за период;
- **поиску** — по имени, логину, e-mail.

Здесь же — кнопки «Активировать/Заблокировать», «Редактировать», «Удалить», «Группы», «Достижения», «Настройки».

### Карточка пользователя

| Поле | Описание |
|---|---|
| **Логин** | Уникальное имя для входа |
| **E-mail** | Уникальный адрес; используется для входа и восстановления пароля |
| **Отображаемое имя** | Как пользователя видят на сайте |
| **Пароль** | Новый пароль (оставьте пустым, чтобы не менять) |
| **Аватар** | Загрузка изображения профиля |
| **О себе (bio)** | Текст в профиле |
| **Сайт** | Ссылка в профиле |
| **Статус** | `active` / `banned` |
| **Администратор** | Флаг `is_admin` — доступ в панель управления |
| **Пользовательские поля** | Если для сущности `user` созданы поля |

> [!WARNING]
> Флаг «Администратор» не заменяет права группы — он открывает доступ в `/admin`. Внутри админки действуют права и защита middleware.

### Профиль на сайте

Пользователь управляет собой сам: `/profile`, `/profile/edit`, `/profile/{username}`. Здесь же — список активных сессий (`/profile/sessions`) с возможностью завершить одну сессию или все сразу (`/profile/terminate-session`, `/profile/terminate-all-sessions`). Удаление аккаунта — `/profile/delete`.

## Группы и права

Права выдаются не пользователю напрямую, а **группе**. Пользователь может состоять в нескольких группах — права суммируются.

| Адрес | Действие |
|---|---|
| `/admin/user-groups` | Список групп |
| `/admin/user-groups/create` | Новая группа |
| `/admin/user-groups/edit/{id}` | Название, описание, «группа по умолчанию» |
| `/admin/users/manage-groups/{id}` | Состав: какие пользователи в группе |
| Кнопка «Права» у группы | Галочки прав |

**«Группа по умолчанию»** назначается новым пользователям при регистрации — как правило, это группа «Читатели» без прав на модерацию.

### Полный список прав в поставке

Права объявляются самими модулями в файле `permissions.php`, поэтому при установке дополнений список пополняется.

**Посты (модуль `posts`):**

| Право | Что разрешает |
|---|---|
| `post_view` | Просматривать материалы |
| `post_comments` | Комментировать материалы |
| `post_rating` | Ставить лайки |
| `post_favorites` | Добавлять в закладки |

**Комментарии (модуль `comments`):**

| Право | Что разрешает |
|---|---|
| `comment_add` | Писать комментарии |
| `comment_add_no_moderations` | Писать без премодерации |
| `comment_edit` | Редактировать свои комментарии |
| `comment_edit_no_moderations` | Редактировать без проверки модератором |
| `comment_delete` | Удалять свои комментарии |

**Профиль (модуль `profile`):**

| Право | Что разрешает |
|---|---|
| `profile_all_view` | Открывать профиль любого пользователя |
| `profile_edit` | Редактировать свой профиль |
| `profile_delete` | Удалять свой аккаунт |
| `email_edit` | Менять e-mail |

> [!TIP]
> Минимальный набор для гостей и новых читателей: `post_view`, `profile_edit`. Всё, что связано с модерацией (`*_no_moderations`, `comment_delete`), выдавайте осознанно.

### Проверка прав в коде

Разработчику: `AuthHelper::can('comment_add')`, `Auth::isLoggedIn()`, `Auth::isAdmin()`. Подробнее — [Права доступа](../developer/03-svoy-kontroller.md#права-доступа).

## Достижения

Достижения — автоматические или ручные награды, которые видны в профиле. Управляются в карточке пользователя и в разделе достижений.

### Типы достижений

| Тип | Как выдаётся |
|---|---|
| **Автоматическое** (`auto`) | Движок сам проверяет условие и выдаёт награду пользователю |
| **Ручное** (`manual`) | Администратор выдаёт вручную, с указанием причины |

### Условия автоматических достижений

| Условие | Что означает |
|---|---|
| `registration_days` | Сколько дней с регистрации |
| `comments_count` | Сколько комментариев оставил |
| `likes_count` | Сколько лайков получил |
| `bookmarks_count` | Сколько раз пост добавили в закладки |
| `login_days` | Сколько дней подряд заходил |

Условий может быть несколько, у каждого — оператор (`>`, `<`, `=`, `>=`, `<=`, `!=`) и значение. Например: «7 дней с регистрации **и** 10 комментариев».

### Что видит администратор

- карточка пользователя → **Достижения**: список выданных, прогресс, кнопка «Выдать» и «Снять»;
- **история выдачи** (`achievement_assignment_history`) — кто, когда и за что выдал достижение, с обязательной причиной;
- возможность **уведомить** пользователя о награде.

### Что видит пользователь

Достижения отображаются в профиле: значок, название, описание, прогресс. Вывод реализован хелперами `renderAchievementBadge()`, `renderAchievementList()`, `getAchievementProgress()`.

### Рекомендации

- 💡 Начинайте с 5–7 достижений: первое действие, серия дней, активность в комментариях.
- 💡 Прогресс мотивирует: пользователь видит «3 из 5 комментариев».
- 💡 Не дублируйте условия — «10 комментариев» и «5 комментариев» одно за другим выглядят странно.

## Безопасность аккаунтов

| Механизм | Где настраивается |
|---|---|
| Ограничение попыток входа | Настройки → Авторизация (`count_auth`, `count_time`) |
| Контрольный вопрос на входе | Настройки → Авторизация (`show_qa`, `qa_param`) |
| Восстановление пароля | Настройки → Авторизация (`disable_restore`); письмо отправляет хелпер `Email` |
| Регистрация | Настройки → Авторизация (`enable_register`, `disable_register_reason`) |
| Активные сессии | Профиль → Сессии; таблица `user_activity` |
| Последние входы и IP | Поля `last_login`, `last_activity`, `last_admin_ip` в таблице `users` |

> [!WARNING]
> Администратор, потерявший доступ, — самая частая аварийная ситуация. Держите минимум два админских аккаунта с разными паролями и доступ к базе данных для восстановления.

## Чек-лист настройки

1. Созданы группы: гости/читатели, редакторы, модераторы, администраторы.
2. Группа по умолчанию назначена.
3. Права выданы по принципу «минимум необходимого».
4. Включены ограничения на попытки входа и капча.
5. Настроены 5–7 автоматических достижений.
6. Проверено восстановление пароля (письмо доходит).
